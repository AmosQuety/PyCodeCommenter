## 2. Decisions the maintainer made (don't reverse without asking)

1. **A TODO may only be removed by stating a fact the code contains** —
   never by a plausible guess. Deterministic generation follows this
   strictly. AI drafts are the one exception, and are always labelled.
   (Origin: `Another_Test_PyCodeCommenter/Feedback/TIER2_TODO_REDUCTION.md`.)
2. **The tool never deletes user code.** That includes `#` comments it
   copies into a docstring.
3. **Duplicates between a copied comment and the new docstring** are
   resolved case by case in `pycodecommenter review` (default: keep the
   comment); never automatically.
4. **Existing NumPy/Sphinx docstrings keep their own style**; the tool
   fills gaps only where that style allows. New docstrings are Google style.
5. **`Methods:` is never generated** (non-standard; guesses only). An
   author's own `Methods:` section is kept.
6. **AI marker text is `(AI-drafted, unreviewed)`**, one per drafted line.
   Changing it would stop the validator recognising existing drafts.
7. **AI output may be written with `--inplace` only together with
   `--accept-ai-drafts`.** Review-first (`--dry-run`, `--output-dir`) needs
   no extra flag. (Supersedes the older "never `--inplace`" note in
   `Docstring Prose Quality — Static Heuristics & AI Generation.md`.)
8. **Bring-your-own-key uses each vendor's official SDK**, installed as an
   optional extra (`[gemini]`, `[openai]`, `[anthropic]`, `[ai]`); the
   default install has no AI dependencies.
9. **Default models are only defaults, and users must be told so** — it is
   printed at the start of every AI run and stated in `--help`, the README
   provider table, and the CLI reference. Anthropic's default is
   `claude-opus-5`.
10. **Hosted service allowance: 25 drafts per caller per day.** When it
    runs out, interactive runs offer to continue with the user's own key.
11. **Python 3.9 dropped** (EOL Oct 2025; the AI SDKs require 3.10).

## 3. How to check a change didn't break anything

1. `pytest .` — the full suite (283+ tests; no network, no SDKs needed).
2. `black .` and `flake8`.
3. **`scratch/compare_generation.py`** — runs an old and a new version of
   the generator over a corpus and compares TODOs, validator issues,
   idempotency, broken output, and code changes. *Broken output* and *code
   changed* must be 0. This caught a real bug in v2.6.0 (see §6).
4. For AI changes, a live smoke run: the maintainer's
   `python packages/Test_PyCodeCommenter/ai_test_batch/*.py` (6 functions)
   through the hosted service should come back with 0 TODOs.

## 4. The hosted AI backend

Separate repo: `/home/amos/dev/python/PyCode Backend`
(`github.com/AmosQuety/PyCodeCommenter-Backend`), Flask on Render's free
tier at `https://pycodecommenter-backend.onrender.com`.

- **Deploying: auto-deploy is off.** Pushing to `main` does nothing until
  someone clicks *Manual Deploy → Deploy latest commit* in Render.
- Endpoints: `/v1/draft-description` (legacy, one sentence),
  `/v2/draft-docstring` (structured slots; the current client uses this),
  `/health`. Contract: `docs/API.md` in that repo.
- Limits: 25 drafts per caller per day, 200 per day overall, 10 requests
  per minute per caller — all in memory, reset on redeploy/cold start.
- The client and backend each have a copy of the drafting prompt and the
  "is this text safe to write" rules (`ai_drafting.py` here,
  `docstring_drafting.py` there). Keep them in step.

Incidents worth knowing (all fixed):
- **Gemini 503 locked every key.** An overloaded model was treated as a key
  failure; one request tripped all four keys' circuit breakers. Model and
  key failures are now handled separately, with model fallback.
- **API keys leaked into logs.** Keys were sent in the URL, and error
  messages printed the URL. Keys now go in the `x-goog-api-key` header.
  The leaked keys were rotated and revoked.
- **Runaway JSON.** `gemini-2.5-flash` in JSON mode sometimes rambled until
  the reply was cut off. Every schema field now has a `maxLength`, and an
  unusable reply moves on to the next model instead of retrying the same.
- **Everyone shared one per-IP limit.** Behind Render's proxy all requests
  came from the proxy's address. `ProxyFix` now restores the caller's
  address (`TRUSTED_PROXY_HOPS=1`). *Open:* confirm from a log line's
  `forwarded_hops=` that 1 is right (a request was sent 2026-09-23 19:54
  UTC for this).

## 5. Known limitations and unverified parts

- **OpenAI, Anthropic and DeepSeek providers have never made a real call**
  (no keys were available). They are tested against fake SDK clients, and
  their call shapes and default models come from the vendors' docs as of
  2026-09. Gemini was verified live. First real use should check these.
- `Compare → bool` return inference assumes built-in operator semantics;
  an overloaded `==` (NumPy, SQLAlchemy) would be documented as `bool`.
- Derived text (a raise condition, a bool description) is kept on later
  runs like author text; editing the code afterwards leaves old wording.
- Class docstrings are not AI-drafted yet: an untyped attribute keeps its
  TODO, and the class summary stays `<Name> class.`.
- An author's hand-wrapped multi-line description is re-emitted as one
  long line (all styles; long-standing). Keeping the author's line breaks
  would need the parser to keep them instead of joining lines.
- The README's `style:` config key isn't wired in, so new docstrings are
  always Google style; existing NumPy/Sphinx ones keep theirs.

## 6. Log (newest first)

- **2026-09-24 — end-of-run summary.** `run_report.GenerationReport`
  counts from the tagged parts (not the output text): new / updated /
  unchanged docstrings, facts, AI lines, gaps, comment docstrings. The CLI
  prints it to stderr. Found and fixed along the way: status messages and
  the consent prompt went to stdout, so with `generate app.py > out.py`
  the prompt landed in the file and the run waited silently. Rule now:
  **stdout = generated code only; status and prompts = stderr**
  (`ai_setup.status`).
- **2026-09-23 — NumPy/Sphinx docstrings keep their style.** The parser
  records a docstring's `style`; `doc_styles.py` renders the same parts
  (`FunctionDoc`, and the new `ClassDoc`) as Google, NumPy or Sphinx. Two
  old tests that asserted conversion to Google were rewritten for the new
  rule. On the corpus, only the two files with NumPy docstrings changed;
  everything else was byte-identical.
- **2026-09-23 — comment blocks become docstrings.** A `#` block directly
  above an undocumented function/class supplies its summary and
  description (author text; the comment stays). Checking the corpus showed
  section banners (`# ----` / `# 1. Baseline: ...`) being taken as function
  descriptions, so blocks with a separator line are now ignored. Uses are
  recorded in `PyCodeCommenter.comment_docstrings` for the run summary and
  `review` (which is where a now-duplicated comment can be removed, one at
  a time, only if the user says yes).
- **2026-09-23 — bug fixes (`2ce15f8`).** Found with
  `compare_generation.py`: the old code turned an escaped `\"\"\"` in a
  docstring into a real `"""`, **producing a file that no longer parsed**.
  Docstrings are now read from source text, not their value. Also: author
  `__init__` summaries kept; the tool's own earlier output (TODOs,
  type-only filler) recognised so `--ai-draft` can improve it; defaults
  stated once; bare `raise NotImplementedError` documented.
- **2026-09-23 — Python 3.10+ (`a5257eb`).**
- **2026-09-23 — bring your own key (`4e477e2`), AI fills every gap
  (`825b8aa`), generator refactor (`4ec3cc7`).** The refactor was verified
  byte-identical on a 21-file corpus before any behaviour changed.
- **2026-09-23 — fact extraction and author-text preservation**, merged to
  `main` as `0a8c419`. TODOs 175 → 118 on an 18-file corpus with no code
  changes and no new validator warnings.
